## Actual cause and behavior

The dark side panel is the game's native battle log overlay. Native code, the original L shortcut and visible before/after observations agree: the map already renders underneath it. There is no extra reserved map width to reclaim. Hiding the actual native panel reveals that existing space without stretching, recentering or changing screen-to-cell coordinates. No extra right-side expansion is claimed.

Preparation hides the native log before the first editor frame and consumes its native toggle action in setup. Every valid battle starts with the log visible. A labelled **Battle log: Hide / Show** button sits between the native log and speed controls during combat. The post-battle field has the same control and follows actual native visibility; hidden means no panel background, border or text. Returning to the editable setup hides it again.

Visibility does not suppress native message creation, clear messages or modify reports. Native L and combat controls keep their native routing outside the custom button's owned mouse gesture. Visible native log bounds take pointer priority over the map. Menus, text input and context controls keep their existing priority. View changes consume the held gesture until release/fresh drawing. Old context popups are dismissed when toggling, avoiding the later native log pass painting over a popup opened while hidden. Existing map geometry, formation controls, zoom, panning, preview, placement and actor lifecycle remain unchanged.

## Limits and how to try it

Windows5.43 only. No Mac implementation/build/test, campaign/replay log control, additional terrain context, full native log export or complete unit-state serialization. Presentation rollback failure cannot be reliably forced in an ordinary process; refusal/error routing is tested offline and reviewed. Close/reopen native restoration was tested with original visibility1; original visibility0 remains untested. Physical sustained right-drag/middle-drag at every zoom was not repeated. A physical wheel gesture over the native combat log was attempted but did not establish scrolling behavior conclusively; native routing/occlusion is protected by offline tests. No claim is made that the battle map became geometrically wider.

Close an old isolated test process, run **SandboxOfElysium-Testen.bat -Muted**, then Sandbox > Battlefield > Open with native deployment. Choose Fortified Hoburg if testing the new siege; A attacks/B defends. Use Fit in setup, place units on either team, and start a battle. Click **Battle log: Hide / Show** during combat or in View post-battle field. Returning to Sandbox must show the saved setup without the log. Existing named scenarios, spells, items and native walls/gate should remain intact.

Both repositories are preserved as separate local source checkpoints. Exact final revisions are recorded in the private checkpoint manifest and the task handoff. No release, PR, push, game file, private diagnostic or modified Extender binary is included.
