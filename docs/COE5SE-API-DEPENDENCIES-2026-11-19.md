## Where to find the tested reference work

The older local reference is separate from these PRs. Its 3.4.4-era source uses `test_field_lifecycle.h` and `lua_test_field_editor.h` for native scope and setup, `lua_test_field_release.h` for context and actor state, and `lua_test_field_deployment.h` with `lua_test_field_initial_deployment.h` for exact reconstruction. Naming and type preview are in `lua_test_field_names.h` and `lua_test_field_monster_inspect.h`. Presentation is in `lua_test_field_zoom.h`, `lua_test_field_log.h` and the fitted sprite helpers in `lua_ui.h`. See the [earlier reference pairing](TEST-RELEASE-CANDIDATE-2026-11-19.md). Its visible tests are historical evidence for that pairing.

## Dependency order

1. Retirement and minimum width can be reviewed independently. Naming builds on owned identity and retirement.
2. Stock native contexts and exact restoration share the field generation and structure provenance contract. Review together with bounded condition and spell restoration. Final provenance builds on this classification.
3. Live unique policy, log visibility and transactional held-item clearing are focused follow-ons. Genuine type View needs the current lifecycle and a revalidated scratch constructor. The viewport work can be reviewed separately. Validate the combined build in the game before treating the new official pairing as release-ready.

The original upstream build was retested against the compatibility checks. It preserved the setup while refusing Guard Tower, saved personal names and the explicit width. The editor startup gate still blocks stock dev. The partial upstream-based review stack supports the tested core workflows but cannot yet replace the complete local reference for release.
