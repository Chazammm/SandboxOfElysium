# Sandbox of Elysium 0.2.0-beta.2 test package

**Tested pairing:** Windows x64 CoE5 **5.43** and official CoE5SE **3.8.2**, the latest main release checked on 2026-11-22. CoE5SE is installed separately. [Official release](https://github.com/musical-pianist/coe5se/releases/tag/CoE5SE-v3.8.2)

## Modded portraits

The preserved beta.1 package reproduced the reported symptom on 3.8.2. With CrabCult loaded, searching for `shell` showed four rows with portraits. Disabling CrabCult and reopening Sandbox left all four names and the old IDs in the browser, but each portrait now showed the question-mark fallback. The base Spearman still drew correctly.

The release kept a single Sandbox controller, and `ensureCatalog` read the catalog only on first use. The browser passed each cached monster ID to native drawing after the game had unloaded CrabCult. This is stale Sandbox catalog data crossing a native content reload. In beta.2, each safe reopen reads the current content tables, replaces stale filter rows and clears incompatible selections. In-memory setups and recovery state are kept under their original ordered mod list. Saved scenario format and dependency checks remain unchanged.

**Visible verification:** In the same beta.2 process, disabled CrabCult, reopened Sandbox and saw zero `shell` matches. Re-enabled CrabCult and reopened Sandbox again. All four portraits and the already placed Shell Priest returned, along with the base Spearman. This run verified CrabCult, not the individual mods shown in the supplied photos.

## Deletion and regression tests

- **Physical input and visible UI:** The new BAT opened the isolated editor. The footer toggle was visible in the tested window and switched from Off to On. Ordinary right-click placed the Shell Priest. With four blue units on the field, the user confirmed that a physical Ctrl-click and held Ctrl + right-drag both worked.
- **Native engine probe:** Held keys were supplied through official CoE5SE, using both left and right Ctrl indices. Tested Off and UI-origin refusal, a single Ctrl-click on an army unit sharing a scenery cell, a drag across a multi-cell unit and another actor, permanent retirement, immediate cell reuse, normal context and placement, Save/Load, battle restoration, Reset and Rematch. The scenery stayed intact.
- **Other official-build runs:** The released beta.1 passed the Castle workflow first. The exact beta.2 ZIP then passed Plain and Castle scenery/lifecycle, Sea field and authoring refusal, loadout and magic with CrabCult, and copied Spirit Eye recovery with safe rejection of a modified definition. The original recovery input hash stayed unchanged.
- **Offline:** 446 cases across 32 suites passed. Focused tests cover the toggle, Ctrl release while the mouse stays down, skipped drag cells, duplicate multi-cell hits, UI crossings, modal gates, native refusal, same-session mod changes, saved dependency checks and fresh sprite handles.
